01 / System workflow

How AgentBoundary works

One connected workflow: an agent proposes work, an independent policy decides what may run, and evidence records the outcome.

Controlled execution pipeline
STEP 01

Define a task

Enter a goal. A temporary task authorization sets the limits for the workflow.

STEP 02

Generate a plan

Fixture mode uses a sample plan; live mode requests Python steps from Vultr inference.

STEP 03

Check authority

The gateway checks whether the task is active and the next action is permitted.

STEP 04

Execute isolated

On a configured Linux host, code runs in a disposable restricted Docker sandbox.

STEP 05

Review evidence

Inspect exit status, output and audit records. Revoke authority before the next step.

Why this project exists: AI agents can do useful work, but broad permissions make mistakes and malicious instructions costly. AgentBoundary separates the model's proposals from the system's permission decisions.

02 / Capabilities

Security controls & what they verify

Features are described according to the current implementation—without claiming full device protection.

Built for The Explorers
CONTROL 01

Task-scoped authority

Only active, unrevoked tasks may execute the next step. Each task has a defined expiration.

CONTROL 02

Immediate re-check

Permission is checked again between steps. Revoking a task prevents later steps from starting.

CONTROL 03

Disposable sandbox

Runs code through a restricted Docker runner on supported Linux hosting, separate from the app process.

CONTROL 04

Network containment

Sandbox network access is disabled, limiting outbound requests from executed code.

CONTROL 05

Resource controls

Execution includes configured CPU, memory, process and time restrictions.

CONTROL 06

Audit and receipts

Execution results and security decisions are recorded with integrity checks. An invalid audit chain needs investigation.

Not implemented as full device security: this web app does not intercept all Cursor/ChatGPT actions, scan personal passwords, protect arbitrary Windows files, or automatically prevent every type of sensitive-data leakage. It only mediates the included agent workflow.
03 / Operator guide

Use the dashboard with confidence

What each control does and what results to expect.

Plan & execute

  • Generate Plan: creates a two-step task using fixture or live inference.
  • Execute next step: sends the approved step to the sandbox runner.
  • Revoke access: blocks any later step for this task.
  • Execution output: shows actual error or result details, not an estimated score.

Containment & audits

  • Run containment test: performs the selected restriction test on a configured Linux Docker host.
  • Refresh evidence: reloads task events and checks audit integrity.
  • Fixture status: demonstrates UI planning only; not evidence of real AI model output.
  • Audit chain INVALID: investigate the stored records and signing key before security claims.
Does AgentBoundary protect every file on my PC?

No. It is not a Windows endpoint firewall. It controls only the operations routed through its own gateway and sandbox.

Why is Vultr required?

For the hackathon's Blast Radius Zero track, Vultr provides the deployed control plane and mandatory Serverless Inference for AI agent calls. A Vultr-hosted working app is required for submission.

Can I test the app on Windows?

Yes, the dashboard, fixture plan, Python unit tests, and authentication can be tested locally. Real sandbox containment must be verified on the configured Linux runtime.

Does an audit hash guarantee security?

No. It can help detect record alteration when the key and verification environment are trusted. It does not prove absence of a data leak or compromise.
